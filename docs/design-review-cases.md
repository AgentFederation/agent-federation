# 设计评审用例：X 运营与闲鱼服务经营

2026-10-31 用户确认：设计同时考虑两种场景，首轮实际实施与验证仍优先 X POC。闲鱼是设计评审用例，不是第二个同时落地的 POC。纸面推演只能发现设计缺口，不能证明跨场景运行已经通过。

## 两个场景各自检验什么

| 维度 | X 持续运营（首个 POC） | 闲鱼服务经营（设计评审用例） |
| --- | --- | --- |
| 持续目标 | 持续提供内容、维护关系与对话 | 发现可服务需求，完成交付，探索可持续经营方式 |
| 工作来源 | 运营窗口、内容库存、评论反馈 | 商品咨询、主动发现的需求、客户素材、修改意见、经营反馈 |
| 交付对象 | 内容受众、对话参与者、协作成员 | 具体客户及内部交接成员 |
| 完成依据 | 发布与回复结果、材料实际采用 | 约定产物、客户确认、付款或退款等相互独立的事实 |
| 后续动作 | 继续对话、补充内容、调整做法 | 等待素材、制作、交付、修改、售后、调整服务方案 |

## 闲鱼场景边界

参考已有经营项目中的商品上架、需求发现、主动服务提议、真实素材接收、制作交付与反馈流程，提炼以下设计用例。以下角色分配与完整流程是待验证的模型映射，不声称现有项目已经按本内核运行。

商品图制作只是具体例子；同一经营组织也可能探索表格处理、文档制作、代码或其他可交付服务。不能将闲鱼模型写死成生图流水线。商品上架与主动需求发现是并行获客来源，不要求每个客户先经过商品发布。

候选持续职责包括经营统筹、商品与需求发现、客户沟通、制作交付、经营复盘。它们可由不同成员承担或按规模合并，不照搬 X 的五成员配置，也不固定绑定某个 runtime。

## 一条用于评审的完整用例

1. 组织依据当前目标和服务能力，维护商品入口，同时发现有具体服务用途的潜在客户。公开信息只是需求线索，客户确认后才成为具体委托。
2. 客户 A 同意试做商品图，但尚未提供素材。沟通成员记录约定范围和待补材料，相关工作等待；客户 B 已提供素材，其制作工作正常推进。
3. 客户 A 发来素材后，事件关联回原客户与委托，唤醒原工作。制作成员获得确认的用途、素材引用、交付要求和期限；不靠重新读取另一成员全部聊天猜测需求。
4. 制作成员交回第一版，内部核验后由沟通成员交付。客户未回复时保持待确认，不能因 Agent 运行结束或文件已发出就记录客户验收通过。
5. 客户提出约定范围内修改，创建关联原委托和产物版本的修订任务；改完再次交付。超出原约定的需求先形成新决定，不静默扩张承诺。
6. 客户确认可用，记录验收事实。免费服务、真实付款、退款与成本分别记账；获得认可不等于产生收入，产生收入不等于盈利。
7. 复盘发现某类交付反复因尺寸信息缺失返工，建议在沟通中补一个必要问题。统筹落实最小调整，后续检查返工与沟通成本；证据不足则继续观察。
8. 组织根据需求与履约证据，决定继续现有服务、调整商品表达或探索另一种服务。尚无人咨询时也可检查机会，而不是只有收到订单才启动。

这是设计推演，不包含客户身份、真实素材、私有价格合同或平台执行授权。

## 评审只盯三个关键点

| 检查点 | 怎样评审 | 什么情况暴露设计缺口 |
| --- | --- | --- |
| 不同来源的工作能否进入同一内核 | 分别沿商品咨询、主动提议和客户回复推演任务创建与接续 | 内核只能按发帖日程触发，或必须编写闲鱼专属调度分支 |
| 多条业务线能否独立等待、交接和返工 | 同时推演 A 等素材、B 制作、A 回复后恢复，并追踪交付版本 | 一个客户等待冻结整个组织；依靠私有会话记住关联；提交即算客户验收 |
| 经营结果能否驱动后续决定 | 将客户认可、收入、成本和返工证据交给成员作继续、调整或不改的决定 | 通用内核内置发布量等单一业务指标；建议没有实施与效果接续 |

设计通过的依据是：每一步都能指出触发来源、负责成员、必要输入、状态变化和结果证据，且两种场景复用相同任务与执行机制。需要补充的业务概念可留在场景层；不能把逻辑上的可表达性宣称为实现可靠性。

## 对当前架构的具体约束

- **关联业务上下文。** 任务和证据需能引用客户、委托、商品或对话等场景对象；内核只需稳定关联方式，不必内置完整客户管理与订单系统。
- **区分执行、交付与业务结果。** Run 成功、内部接收、客户验收、付款是不同事实，具体完成条件由任务合同与场景判定。现有等待、提交、接收、退回机制需能表达它们。
- **复用原业务记录。** 客户素材、订单和成本记录由业务层拥有；共享状态与证据保存必要引用和协作状态，避免复制另一套经营数据库。

无需为此新增一套平台或全面扩充状态机。下一步细化最小执行合同时，用上述双场景逐项检查输入、交付、关联与唤醒条件。软件维护小组保留为未来其他组织形态的候选反例，不纳入当前必做范围。
